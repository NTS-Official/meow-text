# meow-text

在 QQ 里发消息时，句尾自动补上「喵~」。

不是输入法、不是剪贴板工具：它挂一个全局键盘钩子，在你按下**发送键**的瞬间把这次回车拦下来，
先往输入框里补上后缀，再把回车原样送出去。

```
你：  早上好        + Enter
它：  早上好喵~     ← 真正发出去的内容
```

## 现在能用的功能

界面照 WinUI 3 的 `NavigationView` 做：左边一列导航，右边一页内容。

| 页 | 放什么 |
| --- | --- |
| **主面板** | 总开关、当前状态（钩子 / 前台窗口 / 今日与累计次数）、最近 5 条事件 |
| **日志记录** | 完整事件列表、清空、「往当前焦点试注入」、配置文件路径 |
| **偏好** | 主题（白天 / 黑夜 / 跟随系统）、界面语言、关闭窗口行为、开机自启、开关热键、隐藏到后台 / 退出 |
| **高级** | 后缀、发送键、注入方式与延迟、三个保护开关、场景配置、自测框 |

- **总开关**：主面板上的开关，关掉之后钩子仍在，但不再改动任何输入
- **场景配置**：按进程名匹配（QQ 默认开启，TIM / 微信内置但默认关闭，可自行添加）
- **可配置项**：后缀文本、发送键（Enter / Ctrl+Enter）、注入方式（逐字输入 / 剪贴板粘贴）、注入延迟
- **保护开关**：输入框为空时不追加、输入法组词时不动回车、演练模式（只记日志不注入）
- **后台运行**：点 × 时问一句「隐藏到任务栏 / 关闭程序」，可勾「下次不再提示」；托盘图标 + 单实例唤回面板
- **开机自启**（默认关）：在**偏好**页打开，写的是 `HKCU` 的启动项，开机起来后只驻留托盘、不弹面板
- **开关热键**（默认 `Ctrl+Alt+'`）：在**偏好**页点一下录入框、按组合键即可换；不想要就按 Esc 取消录入，或改成别的组合
- **主题**：白天 / 黑夜 / 跟随系统（跟随系统时会实时响应系统切换）
- **界面语言**：面板里随时切（跟随系统 / 简体中文 / English），语言包全量打包，加语言只需丢一个 toml
- **自检与日志**：实时看到钩子状态、前台进程、每次触发/跳过的原因；有新事件时导航栏的「日志记录」会亮小圆点

## 在 QQ 上使用

1. 双击 `meow-text.exe`（或开发时 `cargo run`）。
2. 打开主面板上的**总开关**——「当前状态」里的「键盘钩子」应显示**已挂载**。
3. 到 QQ 聊天窗口里打字，按回车。输入框里应当先出现「喵~」再发出去。

QQ 侧需要满足的条件（都是默认值，一般不用改）：

| 情况 | 处理 |
| --- | --- |
| QQ 设置为「按 Enter 发送消息」 | 默认就是这样，直接可用 |
| 你的 QQ 是「按 Ctrl+Enter 发送」 | 到**高级**页把**发送键**改成 `Ctrl+Enter` |
| QQ 以管理员身份运行 | 本程序也要以管理员身份运行，否则 Windows 会拦下注入（UIPI） |
| 逐字注入在某些版本里没落字 | 把**注入方式**换成「剪贴板粘贴」（临时借用剪贴板，用完恢复文本） |
| 想先观察不真注入 | 勾上**演练模式**，日志里会记录「本应补上…」 |

先用**高级**页里的**自测**框确认一次：点进那个框、打几个字、按 Enter——出现「喵~」说明注入链路是通的，
剩下的就只是 QQ 侧的场景匹配问题（用主面板「前台窗口」对照场景里的进程名即可）。

## 工作原理

```
用户按回车
   │
   ├─ 钩子回调（必须极快，不做任何耗时操作）
   │    ├─ 前台进程匹配场景？
   │    ├─ 是发送键、没按住 Alt、输入法没在组词、输入框里有内容？
   │    ├─ 命中 → 吞掉回车（按下和抬起都吞），把任务丢进队列
   │    └─ 未命中 → 原样放行
   │
   └─ 注入线程
        ├─ 焦点没切走 → 逐字注入「喵~」（或剪贴板粘贴）
        ├─ 重放回车，把消息发出去
        └─ 记账、写日志
```

几个关键细节：

- **吞下就必须还回去**：注入失败也一定会重放回车，绝不会把你的消息卡在输入框里。
- **不认自己**：注入的事件带 `MEOW` 标记且被系统标记为 injected，钩子一律放行，不会自己触发自己。
- **空输入框保护**：靠按键计数启发式判断（打字 +1、退格 −1、剪切清零、发送清零），
  避免在空框里按回车时凭空发出只有「喵~」的消息。
- **组词保护**：用 IMM32 查询输入法组合串，正在拼中文时不动回车（best effort）。

## 主题（白天 / 黑夜 / 跟随系统）

**偏好 → 外观**里三选一：

- **跟随系统**：读 `prefers-color-scheme`，Windows 切成深色时面板立刻跟着变（不用重启）
- **白天** / **黑夜**：写死在配置里，忽略系统设置

三种选择都会同步给原生窗口标题栏（Rust 侧 `set_theme`）。配色全部走 CSS 变量，
浅色是 `ui/styles.css` 顶部的 `:root`（WinUI 默认就是浅色），深色是 `:root[data-theme="dark"]`，
改颜色只需要动这两处。

## 本地化（界面里随时切）

界面上的每一句话都来自 `locales/*.toml`。**所有语言包都在编译期打包进产物**，
所以运行期切换不需要读盘、也不需要重新加载页面：

```
locales/*.toml
        │  build.rs
        ├─> dist/            ui/ 的副本，{{key}} 按「默认语言」替换  → 首屏就是对的，不会闪
        ├─> dist/locale.js   全部语言 + 默认语言（window.MEOW_LOCALES）→ 前端换表重画
        └─> $OUT_DIR/i18n.rs 键表 + 全部语言 + 每个键一个 Key 常量     → 后端 i18n::set_locale 即时生效
```

- **偏好 → 界面语言**的下拉框可以选 **跟随系统 / 简体中文 / English**，选完立刻整套界面（含窗口标题、
  托盘右键菜单）都换过来，并写进配置，下次启动直接用。
- 加语言：往 `locales/` 放一份同名结构的 `xx-YY.toml`（键必须齐全），重新编译即可 ——
  语言列表是从 `locales/` 目录自动发现的，代码不用改。
- 编译期仍然管两件事：
  1. **首屏与兜底语言**：`MEOW_LOCALE=ja-JP` > 系统界面语言 > 回落 `zh-CN`，
     它决定静态 HTML 用哪种语言渲染、以及找不到配置时的兜底。
  2. **键的正确性**：`ui/` 里的 `{{key}}` 找不到就编译失败；Rust 侧是 `Key` 常量，
     写错键名同样是编译错误；各语言包键集合不一致也会直接编译失败。
- 前端静态文字用 `data-i18n` / `data-i18n-placeholder` / `data-i18n-title` 标记，
  动态文字用 `t("key")` 查表 —— 两者都会在切语言时重画。
- 有意留白的文案（比如英文里不写「次」这个量词）直接给空字符串即可。
- 切换语言**不会**重写已经产生的事件日志，历史记录保持当时的语言。

## 后台运行（关窗提示 / 托盘 / 单实例）

点窗口的 **×** 默认会先问一句：

```
要关闭 meow-text 吗？
  ☐ 下次不再提示
  [隐藏到任务栏]  [关闭程序]
```

- **隐藏到任务栏**：窗口收起来，进程和键盘钩子继续跑，在 QQ 里的喵化照常生效
- **关闭程序**：真正退出，喵化停止
- 勾上**下次不再提示**，这次的选择会写进配置，以后点 × 直接照做（不再弹窗）
- 想改回来：**偏好 → 窗口 → 关闭窗口时**可以随时切回 **每次询问**、或直接指定两种行为之一

隐藏之后有两条路把面板叫回来：

1. **任务栏托盘图标**：左键点一下显示面板；右键菜单里有「显示控制面板 / 退出喵化」
2. **再双击一次 `meow-text.exe`**：单实例机制会把已经在后台的那个面板唤到前台，不会开出第二个进程
   （两个实例会装两个键盘钩子、两个托盘图标，所以这里刻意挡住了）

**偏好 → 窗口**里也有个「隐藏到后台」按钮，随时可以手动收起来。

## 开机自启（默认关闭）

**偏好 → 窗口 → 开机自动启动**。打开后写的是当前用户的启动项：

```
HKCU\Software\Microsoft\Windows\CurrentVersion\Run
  meow-text = "D:\...\meow-text.exe" --hidden
```

几个有意的选择：

- **只用 HKCU，不需要管理员权限**，登录时也不会弹 UAC（任务计划程序能提权，但给一个句尾补「喵~」
  的小工具装计划任务太重，还容易被安全软件盯上）
- 命令带 `--hidden`：登录后静默起来，**只留托盘图标不弹面板**，日志里会记一行「这次是开机自启拉起来的」
- **默认关闭**，而且 `--hidden` 之外没有任何隐藏行为：不开这个开关，程序不会往注册表写任何东西
- 每次启动都会拿注册表里的命令和当前的 exe 路径对一遍：**换过目录或版本会自动改成新路径**（日志里会记一行）
- 想手动取消：任务管理器 →「启动」页禁用 `meow-text`，或者把偏好页的开关关掉（都会同步回来）
- 关掉开关时是直接把注册表里的值删掉，所以旧版本残留的启动项也会被清掉

> 注意：启动项登记的是**当前这个 exe 的绝对路径**。如果你把 `meow-text.exe` 挪到别处，
> 下次从新位置启动一次就会自动修正；直接从旧路径开机自启则会失败一次（那个路径已经没东西了）。

## 开关热键（默认 `Ctrl+Alt+'`）

**偏好 → 窗口 → 开关热键**：点一下录入框，直接按你想用的组合键即可（按 Esc 取消本次录入）。
旁边「恢复默认」把它改回 `Ctrl+Alt+'`。按一下热键就能开/关总开关，不用切回面板。

实现上用 `RegisterHotKey`，**不是**再挂一个键盘钩子，这是有意的：

- **不会吃掉你的按键**：不匹配的按键系统根本不通知我们，只有真正命中那一下才收到 `WM_HOTKEY`。
  键盘钩子则是每次按键都要过一遍我们的回调，等于给每一次击键都加一道被拖慢甚至卡住的风险，
  而这个工具的目标恰恰是"别干扰我打字"。
- **注册失败能立刻知道**：组合键被别的程序占了（比如某些截图/录屏工具）会注册失败，
  这时偏好页那行会变黄并写明原因，日志里也有一条。
- 组合键要求**至少带一个修饰键**（Ctrl / Alt / Shift / Win）+ 恰好一个主键：
  字母、数字、F1–F24、方向键、以及 `` ` `` `-` `=` `[` `]` `\` `;` `'` `,` `.` `/` 这些符号。
  光按一个字母不叫热键，注册了也只会到处抢按键。
- 按住不放只触发一次（`MOD_NOREPEAT`）。
- 配置里存的是规范形式（`ctrl+alt+'`，修饰键顺序固定），所以 `ALT + Ctrl + '` 这种写法也会被理成同一个。
- 热键注册在专属线程上：`WM_HOTKEY` 只投递给注册它的线程，界面给的"换一个热键"指令也从那条线程的
  消息循环里处理。

## 已知限制（v1）

- 空框判断是启发式：**鼠标右键粘贴**进来的内容不计入，可能被判成空框而跳过。
- 不判断「消息本身已经以喵~结尾」，会重复追加。
- 引擎只认进程名，不区分 QQ 的哪个窗口（主面板、群聊、搜索框都一样对待）。
- 托盘图标归系统管：Windows 11 默认会把新图标放进「隐藏的图标」浮层里，想让它常驻就手动拖出来。
- 切语言不会重写历史事件日志（保持记录当时的语言）。
- 开机自启走注册表启动项（HKCU），所以是"登录后启动"，不是"开机即启动"；也没有延迟启动、也没有计划任务的提权能力。
- 热键只支持"修饰键 + 一个主键"，不做多键序列（比如先按 Ctrl+K 再按 Ctrl+C）。
- 组合键触发还没做。

## 开发

```bash
cargo test                        # 37 个单测 + 1 个端到端钩子测试 + 6 个本地化一致性检查
cargo test -- --ignored           # 额外跑会真改注册表的那条（autostart 往返）
cargo run                         # 开发模式跑面板（首屏语言按系统语言选）
MEOW_LOCALE=en-US cargo run       # 指定首屏默认语言（界面里仍可随时切）
cargo build --release             # 出 target/release/meow-text.exe
meow-text.exe --probe 300         # 装好钩子、打印一行 JSON 状态后退出（自检用）
meow-text.exe --hidden            # 静默启动（开机自启用的就是这个），退到托盘
```

端到端测试会真的装一个全局钩子、开一个 Win32 编辑框抢前台，验证
「空框回车原样放行」与「有内容回车补喵~」两条路径；抢不到前台焦点时会打印 SKIP 并跳过。

配置与统计都在 `%APPDATA%\dev.meowtext.desktop\config.json`，程序不联网。

## CI 与发版

`.github/workflows/ci.yml`，**跑在 `windows-latest` 上**——这个程序只能在 Windows 上编译运行
（Win32 API + `src/lib.rs` 里的 `compile_error!` 兜底），Tauri 在 Linux 上还要一堆系统库，
所以 ubuntu runner 是没有意义的。

| 任务 | 做什么 |
| --- | --- |
| `check` | `cargo fmt --all -- --check`（行宽见 `rustfmt.toml`）+ `cargo clippy --all-targets -- -D warnings` |
| `test` | `cargo test`：单测 + 本地化一致性检查 + 端到端键盘钩子测试（抢不到前台焦点时它自己跳过） |
| `bundle` | 只在推 `v*` tag 时跑：`tauri build` 出 exe + MSI/NSIS 安装包，挂成 **Release 草稿** |

发版流程：改 `Cargo.toml` / `tauri.conf.json` 里的 `version` → `git tag v0.1.0 && git push origin v0.1.0`，
构建完到 Releases 里把草稿发出来即可。注意 tag 必须是 `v` 开头的（旧的那个 `release` tag 不会触发）。

## 代码结构

| 文件 | 职责 |
| --- | --- |
| `build.rs` | 编译期本地化：发现语言包、生成 `dist/`、`dist/locale.js`、`$OUT_DIR/i18n.rs` |
| `locales/*.toml` | 本地化资源（唯一需要改文案的地方；加文件即加语言） |
| `src/meow.rs` | 纯判定逻辑（该不该喵、用哪个后缀、主题/关闭行为/语言枚举），带单测，不碰 Win32 |
| `src/hook.rs` | 全局键盘钩子、前台进程识别、内容启发式、注入线程 |
| `src/inject.rs` | SendInput 逐字注入、剪贴板兜底、发送键重放 |
| `src/config.rs` | 默认场景、配置读写、统计跨天重置 |
| `src/autostart.rs` | 开机自启：读写 HKCU 的启动项，并在启动时与配置对齐 |
| `src/hotkey.rs` | 全局热键：写法解析/规范化、`RegisterHotKey` 的专属消息循环线程 |
| `src/i18n.rs` | 运行时语言切换：`Key` 常量、`set_locale` / `resolve_tag`、占位符替换 |
| `src/clock.rs` | 本机时间小工具 |
| `src/lib.rs` | Tauri 控制面板：命令、事件、状态、原生窗口主题、托盘图标、关闭流程与单实例 |
| `ui/` | 无打包器的原生 HTML/CSS/JS 面板（WinUI 3 风格的导航栏 + 四个页面，含 `{{key}}` 占位符） |
| `dist/` | build.rs 生成的最终前端资源（已 gitignore，别手改） |
| `tests/i18n_check.rs` | 语言包键一致性、UI 引用完整性、内联标签白名单、产物无残留占位符 |
